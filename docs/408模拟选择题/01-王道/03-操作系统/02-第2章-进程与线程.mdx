**答案：** D

<summary>查看答案与解析</summary>

### 2.3.5 经典同步问题

18. **【王道·卷四-Q27】** 生产者进程和消费者进程的代码如下。生产者进程有一个局部变量nextProduced，以存储新产生的项；消费者进程有一个局部变量nextConsumed，以存储所要使用的项。

```c
while(1){ //producer
/* produce an item in nextProduced */
while((in + 1) % BUFFER_SIZE == out);
/* do nothing */
buffer[in] = nextProduced;
in = (in+1) % BUFFER_SIZE;
}
while(1){ //Consumer
while(in == out);
/* do nothing */
nextConsumed = buffer[out];
out = (out+1) % BUFFER_SIZE;
/* consume the item in nextConsumed */
}
```

条件 $\displaystyle in == out$ 和 $\displaystyle (in + 1)\% BUFFER_SIZE == out$ 成立时，缓冲区中item的数量分别是（  ）。

<div className="choice-options">
<div className="choice-option-row">A. 0, BUFFER_SIZE &emsp;&emsp; B. 0, BUFFER_SIZE-1 &emsp;&emsp; C. BUFFER_SIZE-1, 0 &emsp;&emsp; D. BUFFER_SIZE, 0</div>
</div>

<details>
<summary>查看答案与解析</summary>

**答案：** B

**解析：** 该循环缓冲区采用“牺牲一个存储单元”的方法区分队空与队满。`in` 指向下一次生产者写入的位置，`out` 指向下一次消费者读出的位置。

当

$$
\displaystyle
in=out
$$

时，生产者和消费者指针重合，表示缓冲区为空，item 数量为 0。

当

$$
\displaystyle
(in+1)\bmod BUFFER\_SIZE=out
$$

时，`in` 再前进一步就会与 `out` 重合，表示缓冲区已满。由于必须保留一个空单元用于区分队空和队满，因此最多只能存放

$$
\displaystyle
BUFFER\_SIZE-1
$$

个 item。故两种条件对应的数量分别为 0 和 $\displaystyle BUFFER\_SIZE-1$，选 B。A、D 错误地认为所有数组单元都可用于存放元素；C 将队空和队满的含义颠倒。

</details>

20. **【王道·卷一-Q28】** 假定某系统中有3台设备 $\displaystyle R1$、4台设备 $\displaystyle R2$，它们被 $\displaystyle P_1$、$\displaystyle P_2$、$\displaystyle P_3$ 和 $\displaystyle P_4$ 四个进程互斥共享，且已知这四个进程均以下面所示的顺序使用现有设备：申请 $\displaystyle R1 \rightarrow$ 申请 $\displaystyle R2 \rightarrow$ 申请 $\displaystyle R1 \rightarrow$ 释放 $\displaystyle R1 \rightarrow$ 释放 $\displaystyle R2 \rightarrow$ 释放 $\displaystyle R1$。在系统运行过程中，是否可能产生死锁？（  ）。

<div className="choice-options">
<div className="choice-option-row">A. 不会产生死锁</div>
<div className="choice-option-row">B. 有可能产生死锁，因为 $\displaystyle R1$ 资源不足</div>
<div className="choice-option-row">C. 有可能产生死锁，因为 $\displaystyle R2$ 资源不足</div>

**答案：** B

### 2.4.2 死锁预防

22. **【王道·卷三-Q27】** 为了破坏“请求和保持”条件，提出了两种方法：第一种方法是在进程运行前，必须一次性地申请其在整个运行期间所需的全部资源；第二种方法是允许进程只获得运行初期所需的资源后便可开始运行，进程在运行期间再逐步释放已分配给自己且已使用完毕的全部资源后，才能请求新的资源。在关于这两种方法的说法中，错误的是（  ）。

<div className="choice-options">
<div className="choice-option-row">A. 第一种方法简单、易行且安全，但是降低了资源的利用率</div>
<div className="choice-option-row">B. 第二种方法能使进程更快地完成任务，提高设备的利用率</div>
<div className="choice-option-row">C. 第一种方法发生饥饿的概率很大，第二种方法不会发生饥饿</div>
<div className="choice-option-row">D. 第二种方法是对第一种方法的改进，减小了进程发生饥饿的概率</div>
</div>

<summary>查看答案与解析</summary>

**答案：** C

**解析：** 第一种方法要求进程在开始前一次性获得全部资源，能够彻底破坏“请求和保持”条件，实现简单且安全；但某些暂时不用的资源也会被长期占有，因此资源利用率较低，而且需要资源较多的进程可能长期无法同时获得全部资源，饥饿概率较大，A 正确。

</details>
